# 测试用例运行系统评估方案

## 📋 评估概述

**评估目标**: 全面检查测试用例运行系统的功能完整性、状态管理、报告生成等核心功能  
**评估范围**: 运行逻辑、状态控制、停止机制、报告生成、错误处理、边界情况  
**评估方法**: 功能测试、边界测试、压力测试、用户体验测试

---

## 🎯 评估维度

### 1. 运行逻辑（核心功能）
### 2. 状态管理（生命周期）
### 3. 停止机制（中断控制）
### 4. 报告生成（结果输出）
### 5. 错误处理（异常情况）
### 6. UI 反馈（用户体验）
### 7. 性能表现（效率优化）
### 8. 边界情况（鲁棒性）

---

## 📊 详细评估清单

### 1. 运行逻辑评估

#### 1.1 单命令运行
- [ ] **基础运行**: 点击命令运行按钮，命令能正常执行
- [ ] **状态流转**: 运行前 → 运行中 → 成功/失败，状态转换正确
- [ ] **发送验证**: 命令内容正确发送到串口
- [ ] **响应校验**: 按配置的校验模式正确校验响应（none/standard/custom）
- [ ] **超时机制**: 超时时间到达后正确判定超时
- [ ] **重试机制**: repeatCount > 1 时正确重复执行
- [ ] **成功阈值**: successThreshold 达标时正确判定成功
- [ ] **提前停止**: stopWhenReached=true 时达标后立即停止

#### 1.2 用例运行
- [ ] **递归执行**: 用例递归遍历所有子项（命令 + 子用例）
- [ ] **执行顺序**: 按 children 数组顺序依次执行
- [ ] **跳过禁用**: selected=false 的命令/用例被正确跳过
- [ ] **循环执行**: runCount > 1 时正确循环执行
- [ ] **无限循环**: runCount=0 时持续循环，停止按钮可终止
- [ ] **嵌套用例**: 多层嵌套用例能正常执行
- [ ] **失败策略**: 命令失败时根据 onFailure 正确处理
  - [ ] `continue`: 继续执行后续命令
  - [ ] `end-round`: 结束当前轮次，但继续下一轮
  - [ ] `abort`: 立即终止整个测试
  - [ ] `retry-self`: 重试当前命令（最多 3 次）
  - [ ] `goto`: 跳转到指定命令继续执行

#### 1.3 特殊命令类型
- [ ] **URC 守护**: urc-guard 类型命令后台监听，不阻塞后续执行
- [ ] **脚本命令**: script 类型命令能正确调用外部脚本
- [ ] **文件发送**: fileData 关联的文件能按分包设置发送
- [ ] **变量替换**: 命令内容中的 ${varName} 正确替换为变量值
- [ ] **变量提取**: extractConfig 配置的变量能从响应中提取并保存

#### 1.4 双串口支持
- [ ] **端口路由**: 命令指定 txPort/rxPort 时发送/接收路由正确
- [ ] **继承机制**: 未指定时正确继承用例的 targetPort
- [ ] **交叉通信**: P1 发 P2 收的场景能正常工作
- [ ] **ALL 广播**: sendTarget=ALL 时同时向 P1 和 P2 发送

---

### 2. 状态管理评估

#### 2.1 命令状态
- [ ] **pending**: 初始状态，等待执行
- [ ] **running**: 执行中，图标旋转动画
- [ ] **success**: 执行成功，绿色 ✓ 图标
- [ ] **failed**: 执行失败，红色 ✗ 图标
- [ ] **interrupted**: 用户中断，橙色图标
- [ ] **skipped**: 跳过执行，灰色图标

#### 2.2 用例状态
- [ ] **状态聚合**: 用例状态正确反映子项整体状态
- [ ] **running**: 任一子项运行中时用例显示 running
- [ ] **success**: 所有子项成功时用例显示 success
- [ ] **failed**: 任一子项失败且策略为 abort 时用例显示 failed
- [ ] **interrupted**: 用户停止时用例显示 interrupted

#### 2.3 状态持久化
- [ ] **刷新保留**: 页面刷新后运行状态不应丢失（或明确重置）
- [ ] **历史记录**: 上次运行的状态信息能查看
- [ ] **状态重置**: "清空状态"功能能将所有状态重置为 pending

---

### 3. 停止机制评估

#### 3.1 停止按钮
- [ ] **单命令停止**: 运行中的单命令能正常停止
- [ ] **用例停止**: 运行中的用例能正常停止（中断递归执行）
- [ ] **按钮状态**: 运行中显示"停止"，空闲时显示"运行"
- [ ] **禁用状态**: 不可停止的命令（如已完成）按钮正确禁用
- [ ] **响应速度**: 点击停止后应在 1 秒内响应

#### 3.2 暂停/恢复（如果支持）
- [ ] **暂停功能**: 暂停按钮能正确暂停执行
- [ ] **恢复功能**: 恢复按钮能从暂停点继续执行
- [ ] **状态保持**: 暂停期间状态不丢失

#### 3.3 中断清理
- [ ] **资源释放**: 停止后正确释放串口、定时器等资源
- [ ] **状态一致**: 停止后所有状态标记为 interrupted
- [ ] **日志记录**: 终端显示"用户中断"等明确信息

---

### 4. 报告生成评估

#### 4.1 运行报告（如果有）
- [ ] **报告触发**: 用例执行完成后能生成运行报告
- [ ] **报告内容**: 包含执行时间、成功/失败数量、详细日志
- [ ] **格式正确**: 报告格式清晰易读（JSON/HTML/Markdown）
- [ ] **导出功能**: 能导出报告到文件

#### 4.2 统计信息
- [ ] **执行统计**: 显示总命令数、成功数、失败数、跳过数
- [ ] **时间统计**: 显示总执行时间、平均命令耗时
- [ ] **成功率**: 显示整体成功率百分比
- [ ] **循环统计**: 多轮循环时显示每轮统计

#### 4.3 日志记录
- [ ] **命令日志**: 每条命令的发送内容、响应内容、执行结果
- [ ] **时间戳**: 每条日志都有准确的时间戳
- [ ] **颜色区分**: 成功/失败用不同颜色区分
- [ ] **日志导出**: 能导出完整日志到文件

### 5. 错误处理评估

#### 5.1 串口错误
- [ ] **串口断开**: 运行中串口断开时正确提示并停止
- [ ] **发送失败**: 串口发送失败时正确处理
- [ ] **无响应**: 串口无响应时超时机制生效
- [ ] **错误提示**: 错误信息清晰明确，便于排查

#### 5.2 配置错误
- [ ] **无效配置**: 检测并提示无效的命令配置
- [ ] **缺失端口**: 未连接串口时提示用户
- [ ] **循环依赖**: goto 造成的循环依赖能检测并提示
- [ ] **变量缺失**: 引用不存在的变量时提示

#### 5.3 脚本错误
- [ ] **脚本不存在**: 脚本文件不存在时明确提示
- [ ] **执行失败**: 脚本执行失败时捕获错误信息
- [ ] **超时处理**: 脚本执行超时时正确终止

### 6. UI 反馈评估

#### 6.1 视觉反馈
- [ ] **运行动画**: 运行中的命令/用例有明显动画（旋转/闪烁）

- [ ] **Toast 通知**: 关键操作完成后有 toast 提示
- [ ] **错误提示**: 错误信息显著且易于理解

### 7. 性能表现评估

#### 7.1 执行效率
- [ ] **启动速度**: 点击运行到开始执行 < 100ms
- [ ] **切换流畅**: 命令间切换无明显卡顿
- [ ] **大用例**: 100+ 命令的用例能流畅运行
- [ ] **并发处理**: 双串口同时运行不冲突

#### 7.2 资源占用
- [ ] **内存稳定**: 长时间运行内存不泄漏

- [ ] **日志限制**: 日志过多时自动清理旧记录

#### 7.3 响应速度
- [ ] **状态更新**: 状态变化 < 100ms 反映到 UI
- [ ] **日志输出**: 日志写入终端 < 50ms
- [ ] **停止响应**: 停止命令后 < 1s 停止执行

---

### 8. 边界情况评估

#### 8.1 极端配置
- [ ] **空用例**: 空用例（无子项）能正常处理
- [ ] **空命令**: 空命令（content=""）能正常处理或提示
- [ ] **超长命令**: 超长命令内容（>1KB）能正常发送
- [ ] **超大用例**: 1000+ 命令的超大用例能加载和运行

#### 8.2 异常输入
- [ ] **特殊字符**: 命令中包含特殊字符（\0, \r\n）能正确处理
- [ ] **无效正则**: 自定义校验的正则表达式无效时提示
- [ ] **负数配置**: timeout/delay 等为负数时拒绝或修正
- [ ] **超大数字**: repeatCount 为极大值（如 999999）时能处理

#### 8.3 并发场景
- [ ] **快速点击**: 快速连续点击运行按钮不会重复执行
- [ ] **同时运行**: 不允许多个用例同时运行（或明确支持）
- [ ] **运行中编辑**: 运行中编辑命令配置不影响正在执行的实例

## 🧪 测试用例设计

### 测试用例 1: 基础运行流程
```yaml
名称: 测试基础命令运行
步骤:
  1. 连接串口
  2. 创建简单命令: AT+CSQ (校验模式: standard, 超时: 1000ms)
  3. 点击运行按钮
  4. 观察状态变化: pending → running → success/failed
  5. 检查终端输出: 发送内容、响应内容、结果
预期结果: 
  - 命令执行成功
  - 状态图标显示绿色 ✓
  - 终端显示 "OK" 响应
```

### 测试用例 2: 用例循环执行
```yaml
名称: 测试用例循环执行
步骤:
  1. 创建用例，包含 3 条命令
  2. 设置 runCount = 3
  3. 点击用例运行按钮
  4. 观察执行过程
预期结果:
  - 用例执行 3 轮
  - 每轮都执行全部 3 条命令
  - 终端显示 9 次命令发送（3×3）
  - 用例最终状态为 success
```

### 测试用例 3: 失败处理策略
```yaml
名称: 测试 onFailure 策略
步骤:
  1. 创建用例，包含 5 条命令
  2. 第 3 条命令设置为必然失败（校验不匹配）
  3. 测试不同的 onFailure 策略：
     a. continue: 失败后继续执行第 4、5 条
     b. abort: 失败后立即停止，不执行后续
     c. retry-self: 重试第 3 条命令 3 次
预期结果:
  - continue: 执行 5 条命令，第 3 条失败
  - abort: 执行 3 条命令，第 3 条失败后停止
  - retry-self: 第 3 条重试 3 次，全部失败，然后继续
```

### 测试用例 4: 停止机制
```yaml
名称: 测试停止按钮
步骤:
  1. 创建用例，包含 10 条命令，每条 delay=500ms
  2. 点击用例运行按钮
  3. 执行到第 3 条命令时点击停止按钮
  4. 观察停止效果
预期结果:
  - 执行立即停止
  - 第 4-10 条命令不再执行
  - 已执行命令状态保持（1-2 成功，3 interrupted）
  - 未执行命令状态为 pending
  - 用例状态为 interrupted
```

### 测试用例 5: 双串口交叉通信
```yaml
名称: 测试双串口交叉通信
步骤:
  1. 连接 P1 和 P2 两个串口
  2. 创建命令: txPort=P1, rxPort=P2
  3. 运行命令
  4. 检查发送和接收端口
预期结果:
  - 命令从 P1 发送
  - 响应从 P2 接收
  - 终端正确标注 [P1 TX] 和 [P2 RX]
```

### 测试用例 6: 变量提取与替换
```yaml
名称: 测试变量系统
步骤:
  1. 创建命令1: AT+CSQ，提取信号强度到 ${signal}
  2. 创建命令2: 发送 "Signal is ${signal}"
  3. 运行用例
预期结果:
  - 命令1 执行后变量 ${signal} 被赋值（如 "25"）
  - 命令2 发送内容为 "Signal is 25"（变量正确替换）
```

### 测试用例 7: URC 守护
```yaml
名称: 测试 URC 后台守护
步骤:
  1. 创建 urc-guard 命令，匹配 "+CGREG: 1"
  2. 创建后续 3 条普通命令
  3. 运行用例
  4. 在执行普通命令期间，模块主动上报 +CGREG: 1
预期结果:
  - URC 命令立即返回，不阻塞后续命令
  - 普通命令正常执行
  - 收到 URC 上报时，URC 命令状态变为 success
  - 终端显示 "URC 匹配成功"
```

### 测试用例 8: 边界情况
```yaml
名称: 测试边界情况
步骤:
  1. 空用例（无子项）→ 点击运行
  2. 空命令（content=""）→ 点击运行
  3. 超长命令（10KB）→ 点击运行
  4. 超大 repeatCount（999999）→ 点击运行后立即停止
预期结果:
  - 空用例: 提示"无可执行命令"或立即完成
  - 空命令: 提示错误或自动跳过
  - 超长命令: 正常发送（或提示超长）
  - 超大 repeatCount: 能正常停止，不卡死
```

## 🔍 检查方法

### 自动化检查（代码层面）
```bash
# 1. 类型检查
npm run typecheck

# 2. 单元测试（如果有）
npm run test

# 3. 端到端测试（如果有）
npm run test:e2e
```

### 手动检查（功能层面）
1. **逐项测试**: 按照评估清单逐项测试，记录结果
2. **场景模拟**: 使用真实串口设备或虚拟串口模拟实际场景
3. **压力测试**: 运行长时间、大量命令的压力测试
4. **用户视角**: 站在用户角度评估操作流畅度和直观性

### 代码审查（质量层面）
1. **逻辑审查**: 检查 `useTestExecution.ts` 中的执行逻辑
2. **状态管理**: 检查 `testCaseStore.ts` 中的状态管理
3. **错误处理**: 检查是否有完善的 try-catch 和错误提示
4. **性能优化**: 检查是否有性能瓶颈（如无限循环、内存泄漏）
